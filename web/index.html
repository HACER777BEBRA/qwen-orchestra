Модели и промпты роутера

Как пользоваться

Здесь настраивается пул моделей оркестра и правила Auto. Сначала выберите модель роутера — она решает, какой тир взять при неоднозначных запросах.

Пул

  • Модель — тег Ollama или id OpenRouter; карточка = одна модель.
  • Тир — tiny…frontier для Auto/эскалации, либо «не участвует в роутинге» (только ручной выбор в чате).
  • Rank — сила при выборе на тире и эскалации после selfcheck (больше = сильнее). Без тира не используется.
  • Промпт — когда роутеру выбирать этот тир (учитывается только у моделей с тиром).
  • Самопроверка — браковать ли отказы («не могу») и неуверенность («не знаю»); списки фраз редактируются. По умолчанию оба включены.
  • Удалить — убрать модель из пула (последнюю удалить нельзя).

OpenRouter

Внешняя модель (Claude, GPT и т.д.): задайте API-ключ, id вида anthropic/claude-sonnet-4, тир/rank по желанию. Роутер и самопроверка остаются локальными; web-tools на OpenRouter пока не работают.

Rank

При провале ответа оркестр переходит к следующей available-модели с большим rank. Несколько моделей могут делить один тир — для ответа берётся с max rank.

Добавить в пул

Выберите провайдер и модель; тир опционален. «Сохранить» пишет settings.json. Ключ OpenRouter — в secrets.json.

Самопроверка ответа

По умолчанию короткий отказ («не могу»…), неуверенность («не знаю»…) или LLM-вердикт «не по теме» бракуются и запускают retry. Можно выключить или заменить список фраз (по одной на строку).

План сложных запросов

Два независимых вопроса в одном сообщении (или список пунктов) разбиваются на шаги, ответы склеиваются. Планировщик — модель из селекта выше. Классификатор «нужен ли план» — модель роутера. В чат: сворачиваемое окно плана сверху, стрим каждого пункта в своём окне, затем склейка в теле сообщения.

Пул моделей: укажите тир для Auto или оставьте «не участвует в роутинге». Несколько моделей на один тир допустимы (приоритет — rank).
